    カプセル化

    🎯 このレッスンの目標

    • カプセル化の目的を理解する
    • アクセス修飾子を使い分けられる
    • getter/setterを作成できる
    • 適切にデータを保護できる

    学習時間: 約2時間

    1. カプセル化とは？

    データを「隠して守る」仕組み

    // ❌ 問題のあるコード
public class BankAccount {
    int balance = 10000;  // 残高
}

BankAccount account = new BankAccount();
account.balance = -1000000;  // 不正な値を設定できてしまう！

    カプセル化で解決

    // ✅ カプセル化したコード
public class BankAccount {
    private int balance = 10000;  // privateで隠す

    public int getBalance() {
        return balance;
    }

    public void deposit(int amount) {
        if (amount > 0) {
            balance += amount;
        }
    }
}

    2. アクセス修飾子

    4つのアクセス修飾子

    修飾子 同クラス 同パッケージ サブクラス 全体
    private ✅ ❌ ❌ ❌
    (なし) ✅ ✅ ❌ ❌
    protected ✅ ✅ ✅ ❌
    public ✅ ✅ ✅ ✅

    実務での使い分け

    対象 推奨修飾子
    フィールド private
    getter/setter public
    内部処理メソッド private
    外部公開メソッド public

    3. getter と setter

    getter: 値を取得するメソッド

    public class Student {
    private String name;

    // getter
    public String getName() {
        return name;
    }
}

    setter: 値を設定するメソッド

    public class Student {
    private String name;

    // setter
    public void setName(String name) {
        this.name = name;
    }
}

    命名規則

    フィールド getter setter
    name getName() setName()
    age getAge() setAge()
    active (boolean) isActive() setActive()

    4. 値の検証（バリデーション）

    setterで値をチェック

    public class Student {
    private String name;
    private int age;

    public void setName(String name) {
        if (name != null && !name.isEmpty()) {
            this.name = name;
        }
    }

    public void setAge(int age) {
        if (age >= 0 && age <= 150) {
            this.age = age;
        }
    }
}

    実践例：銀行口座

    public class BankAccount {
    private String accountNumber;
    private String ownerName;
    private int balance;

    public BankAccount(String accountNumber, String ownerName) {
        this.accountNumber = accountNumber;
        this.ownerName = ownerName;
        this.balance = 0;
    }

    // 残高照会（getterのみ、setterなし）
    public int getBalance() {
        return balance;
    }

    // 預入
    public boolean deposit(int amount) {
        if (amount <= 0) {
            System.out.println("エラー: 金額は正の値を指定してください");
            return false;
        }
        balance += amount;
        System.out.println(amount + "円預け入れました。残高: " + balance + "円");
        return true;
    }

    // 引出
    public boolean withdraw(int amount) {
        if (amount <= 0) {
            System.out.println("エラー: 金額は正の値を指定してください");
            return false;
        }
        if (amount > balance) {
            System.out.println("エラー: 残高不足です");
            return false;
        }
        balance -= amount;
        System.out.println(amount + "円引き出しました。残高: " + balance + "円");
        return true;
    }
}

    5. 読み取り専用フィールド

    setterを作らない

    public class Product {
    private final String productId;  // 変更不可
    private String name;
    private int price;

    public Product(String productId, String name, int price) {
        this.productId = productId;
        this.name = name;
        this.price = price;
    }

    // productIdはgetterのみ（変更不可）
    public String getProductId() {
        return productId;
    }

    // name, priceはgetter/setter両方あり
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }

    public int getPrice() { return price; }
    public void setPrice(int price) {
        if (price >= 0) {
            this.price = price;
        }
    }
}

    6. Eclipseでの自動生成

    getter/setterの自動生成

    1. クラス内で右クリック
    2. ソース → getterおよびsetterの生成
    3. 対象フィールドを選択
    4. 生成をクリック

    コンストラクタの自動生成

    1. クラス内で右クリック
    2. ソース → フィールドを使用してコンストラクターを生成
    3. 対象フィールドを選択
    4. 生成をクリック

    7. 実践：従業員管理

    public class Employee {
    private String employeeId;
    private String name;
    private String department;
    private int salary;

    // コンストラクタ
    public Employee(String employeeId, String name, String department, int salary) {
        this.employeeId = employeeId;
        this.name = name;
        this.department = department;
        this.salary = salary;
    }

    // getter
    public String getEmployeeId() { return employeeId; }
    public String getName() { return name; }
    public String getDepartment() { return department; }
    public int getSalary() { return salary; }

    // setter（employeeIdは変更不可）
    public void setName(String name) {
        if (name != null && !name.isEmpty()) {
            this.name = name;
        }
    }

    public void setDepartment(String department) {
        this.department = department;
    }

    public void setSalary(int salary) {
        if (salary >= 0) {
            this.salary = salary;
        }
    }

    // 昇給
    public void raise(int amount) {
        if (amount > 0) {
            this.salary += amount;
            System.out.println(name + "の給与を" + amount + "円昇給しました");
        }
    }

    // 情報表示
    public void showInfo() {
        System.out.println("ID: " + employeeId);
        System.out.println("名前: " + name);
        System.out.println("部署: " + department);
        System.out.println("給与: " + salary + "円");
    }
}

    使用例

    public class Main {
    public static void main(String[] args) {
        Employee emp = new Employee("E001", "田中太郎", "開発部", 300000);

        emp.showInfo();
        System.out.println("---");

        emp.raise(50000);
        emp.setDepartment("マネージャー");

        System.out.println("---");
        emp.showInfo();
    }
}

    8. まとめ

    このレッスンで学んだこと

    項目 説明
    カプセル化 データを隠して保護する仕組み
    private クラス内からのみアクセス可能
    public どこからでもアクセス可能
    getter フィールドの値を取得
    setter フィールドの値を設定（検証可能）

    カプセル化のメリット

    1. データの保護: 不正な値を防ぐ
    2. 変更の容易さ: 内部実装を変更しても外部に影響しない
    3. コードの安全性: バグを減らせる

    基本パターン

    public class ClassName {
    private String field;  // privateで隠す

    public String getField() {  // getter
        return field;
    }

    public void setField(String field) {  // setter（検証付き）
        if (field != null) {
            this.field = field;
        }
    }
}
